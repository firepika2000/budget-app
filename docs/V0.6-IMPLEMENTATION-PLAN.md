# v0.6 Insights Implementation Plan

Status: **ENGINEERING COMPLETE — HUMAN ACCEPTANCE PENDING**

This plan implements the v0.6 Insights milestone without changing the authoritative ledger,
allocation, reconciliation, or forecast semantics. The server owns financial classification and
exact integer-minor-unit aggregation. Swift Charts consumes report DTOs and may convert exact totals
to floating-point values only for presentation geometry.

## Delivered foundation

- Spending Breakdown is transaction-backed, split-aware, refund-netted, transfer-excluding, filtered,
  permission-scoped, and drillable through the shared transaction editor.
- Income vs. Spending totals use the same server classification and retain contributing transaction IDs.
- Date, account, category/group, member, payee, type, clearing, and tracking filters are available where
  supported by the canonical report contract.

## Checkpoints

### 1. Income and spending trends

- [x] Server-authoritative monthly periods within any inclusive requested range.
- [x] Exact income, spending, difference, and contributing transaction IDs per period.
- [x] Partial first/last calendar months are explicitly bounded by the requested dates.
- [x] Swift API contract and native Swift Charts visualization.
- [x] Demo/live contract parity.
- [x] Regression coverage for splits, refunds, transfers, boundaries, and chart presence.

### 2. Net worth

- [x] Server-authoritative historical net worth series.
- [x] Visible-account and tracking-account scope with exact account contributions.
- [x] Assets, liabilities, total net worth, filters, and account drill-through.
- [x] Native accessible chart and meaningful empty states.

### 3. Budget and target performance

- [x] Assigned versus spent and category availability context.
- [x] Target funding/performance explanations without treating targets as money.
- [x] Overspending, RTA, rollover, and recommended-funding context from canonical planning data.
- [x] Category drill-through using existing production report/transaction views where a category has contributing activity.

### 4. Interaction and closure

- [x] Time-point selection for income/spending and net-worth trends, with contextual exact values and transaction/account drill-through.
- [x] Filter parity audit: report-meaningful account/category/group/member/payee/type/tracking,
  clearing/reconciled, flag, and tag filters use authoritative server predicates; transaction-only
  filters do not pretend to filter net worth.
- [x] Restricted-member aggregate/privacy regression matrix for report resources, member filters, and mixed visible/hidden aggregates.
- [x] Performance/load coverage for one-, five-, and ten-plus-year net-worth histories.
- [x] Net-worth ledger correctness for opening history, inclusive boundaries, liabilities,
  credit-card payments, reconciliation adjustments, and void/reversal pairs.
- [x] Local-calendar, DST, leap-day, month, year, and inclusive server-range boundary coverage.
- [x] Full backend, package, native, UI, semantic accessibility, dark-mode, accessibility-size, and
  production XCUITest automation.
- [ ] Human visual and VoiceOver gesture-level acceptance. This is intentionally not claimed by
  automated engineering evidence.

### 5. Spending depth

- [x] Category/group trends and monthly averages.
- [x] Payee trends with bounded server-authoritative aggregation (top 12 by default, API maximum 25).
- [x] Progressive group → category and payee → transaction drill context through shared production views.
- [x] Visualization switching without losing the active report date/filter context.

### 6. Historical budget performance

- [x] Assigned-versus-spent history, aggregate category availability, and rollover trends.
- [x] Overspending and Unassigned history from canonical ledger/allocation observations.
- [x] Month-boundary, Move Money, refund, split, and credit-reserve correctness.

### 7. Debt and resilience

- [x] Server-authoritative debt totals, account contribution, principal reduction, credit-card debt,
  bounded history, account filtering, permission scoping, and native account drill-through.
- [x] Debt/report cross-consistency for card purchases and payments, loan payments, reconciliation
  adjustments, void/reversal pairs, multiple accounts, zero/hidden debt, and 1/5/11-year histories.
- [x] Payoff projection explicitly deferred to v0.8: the current account model does not contain
  authoritative APR, minimum-payment, amortization, or principal/interest allocation inputs, so v0.6
  does not invent one. The subsequent Debt Cost & Payoff product decision confirms that v0.8 must add
  those authoritative optional terms and a provider-neutral exact projection engine; the missing
  model is no longer a reason to omit the capability from that milestone.
- [x] Transparent cash buffer, scheduled income/outflows, lowest projected balance, and 30-day
  expected-margin metrics; no opaque composite score.
- [x] Essential-expense and emergency-fund coverage are explicitly unavailable because categories
  lack authoritative classifications; required obligations are reported as scheduled outflows rather
  than falsely claiming every schedule is mandatory.
- [x] Metrics blocked by missing interest/principal or category-purpose metadata are documented in
  the API and production UI rather than replaced by assumptions.

### 8. Export and operational quality

- [x] Useful open-format CSV report export distinct from full-fidelity backup, with exact minor-unit
  observations, authorization gating, bounded report ranges, and spreadsheet-formula hardening.
- [x] Deterministic ordering, validated ranges, bounded payloads, stable empty states, and nullable-field
  audit. Historical ranges are bounded to 600 calendar months; exact aggregates remain complete while
  drill-through provenance is capped at 500 unique transaction IDs with explicit truncation metadata.
- [x] One-, five-, and ten-plus-year synthetic scale characterization across report families, plus a
  PostgreSQL 17 plan regression with 50,000 ledger rows and production composite report indexes.
- [x] Authentication, budget/resource IDOR, archived-resource, and filter-manipulation audit for every report.

## Non-goals

- No predictive advice, bank connectivity, scenario mutation, or client-owned financial definitions.
- No report may mutate transactions, allocations, balances, targets, schedules, or reconciliation state.
- No v0.6 engineering checkpoint constitutes human acceptance or release tagging.
