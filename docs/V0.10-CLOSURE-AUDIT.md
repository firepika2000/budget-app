## Local Device approval and recovery follow through

Current implementation evidence extends through `f1ae5c6` on `codex/development`.
Local Device rejects duplicate row choices and unknown approval actions before posting
(`db8f8bf`). Current account access, transaction capabilities and import ownership are checked
before cached reviews or mutations are returned (`2c3b569`); this matches the server's import
boundary rather than relying only on the reconciliation screen's permission check.

Financial validation now rolls back earlier rows when a later row fails (`81d25bf`). Approval
and undo each publish their ledger changes and review marker in one SQLite transaction
(`f64964c`, `5bc9321`). Injected marker-write failures preserve the previous balances and review;
retry and repository reconstruction produce exactly one accepted deposit or reversal. Conditional
review version/status checks run inside the write transaction, rejecting stale approvals and
cancellations before replacement; stale repositories rehydrate accepted state (`dcb3562`).
The focused SQLite run passed three tests, and the native stale-state/authorization run passed
two tests. These runs do not establish concurrency safety for unrelated Local Device command types.

Statement review now explicitly distinguishes income from a categorized refund (`2b09cdb`).
Positive rows default to income; selecting a category preserves that refund relationship through
canonical posting on Local Device and Budget Server. Tracking accounts do not offer budget-category
choices. The focused server import route suite passed 13 tests, and two native tests verified
exact category activity/Available, income/RTA and financial rollback semantics.

Payees created by accepted imports use the same canonical identity resolution as ordinary entry
(`743ec02`). Alias and payee IDs survive projection/reopen; financial rollback includes the payee
registry. The payee and alias follow-through evidence is recorded in `V0.5-CLOSURE-AUDIT.md`.

## Implemented scope

The shared production reconciliation workflow imports CSV, TSV, explicitly delimited text,
OFX/QFX, QIF, SWIFT MT940, ISO 20022 CAMT.052/.053/.054, and conservatively recognized PDF rows.
Budget Server and Local Device providers use the same staged review contract:

- bounded parsing with exact integer minor-unit money and explicit date/number conventions;
- money-neutral staging before any ledger mutation;
- account-scoped, permission-filtered matching and duplicate suggestions;
- explicit post/skip decision for every candidate;
- atomic approval through canonical transaction creation;
- durable, bounded review history with cancellation and canonical undo;
- alias-aware first-class payee and default-category suggestions without creating identities during staging;
- fail-closed private-safe errors and XML declaration/entity rejection;
- Local Device persistence through relaunch and encrypted backup/restore.

Bank-specific PDF profiles and transfer auto-matching remain enhancements. Unsupported or ambiguous
files fail clearly and can be replaced with a structured export; the app never guesses financial facts.
Direct bank connectivity is v0.13 work and is not part of file import.

1. Reconcile the account and choose **Import Statement**. Import one structured bank export (CSV,
