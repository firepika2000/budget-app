## Implemented scope

The shared production reconciliation workflow imports CSV, TSV, explicitly delimited text,
OFX/QFX, QIF, SWIFT MT940, ISO 20022 CAMT.052/.053/.054, and conservatively recognized PDF rows.
Budget Server and Local Device providers use the same staged review contract:

- bounded parsing with exact integer minor-unit money and explicit date/number conventions;
- money-neutral staging before any ledger mutation;
- account-scoped, permission-filtered matching and duplicate suggestions;
- explicit post/skip decision for every candidate;
- atomic approval through canonical transaction creation;
- durable, bounded review history with cancellation and canonical undo;
- alias-aware first-class payee and default-category suggestions without creating identities during staging;
- fail-closed private-safe errors and XML declaration/entity rejection;
- Local Device persistence through relaunch and encrypted backup/restore.

Bank-specific PDF profiles and transfer auto-matching remain enhancements. Unsupported or ambiguous
files fail clearly and can be replaced with a structured export; the app never guesses financial facts.
Direct bank connectivity is v0.13 work and is not part of file import.

## Consolidated human acceptance

Use one disposable account; do not reset retained household or Simulator data.

1. Reconcile the account and choose **Import Statement**. Import one structured bank export (CSV,
   OFX/QFX, or QIF). If CSV, choose a custom column mapping and return from a column selector without
   losing it; canceling file selection must leave the reconciliation draft intact. Review every row,
   skip one duplicate candidate, and approve the rest. Include
   one refund assigned to its original category and one ordinary deposit left as income.
2. Confirm balances and Activity change only after approval, survive relaunch, and the batch appears
   in Statement Import History.
3. Open the approved batch and use Undo. Confirm the canonical reversal/void behavior is visible and
   reconciled or otherwise ineligible transactions prevent partial undo.
4. With a restricted household member, confirm an inaccessible account/import cannot be listed,
   opened, staged, approved, or inferred through duplicate/payee suggestions.
