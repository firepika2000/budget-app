before/after recipient, source, amount, cadence/date, rollover, pause state and destination splits.

This closes the confirmed issuance scale gap; consolidated human interaction acceptance remains open.

Other mutable histories still require a scope-by-scope read/export audit; endpoint existence alone
does not prove complete explanation, pagination, migration preservation or privacy. No unsupported
claim of full v0.12 coverage is made here.

Category/group history inspection found that the original presentation explained only the first
recognized field change, despite retaining complete snapshots. Expandable Change details now expose
all changed names, groups, symbols, notes, sort order, archive state, essential/emergency classification
and delegated member. Current authorized workspace names resolve resource identities; unavailable
groups/members receive neutral labels rather than raw identifiers. Identity changes remain observable
even when both names resolve to the same unavailable label. Creation has explicit unset before-values,
and unchanged fields are omitted. This is read-only explanation, not a new accounting model.

Payee history inspection found the same first-field-only presentation gap, plus only one alias
addition/removal shown after a merge. Expandable Payee decision details now expose every returned
name/archive/merge/default-category change and every added/removed alias in stable order. Suggested

missing names receive neutral labels instead of loading the entire payee directory or displaying IDs.
Privacy-redacted snapshots do not synthesize aliases or hidden fields. Existing pagination remains
bounded and now guards overlapping reads. Human interaction acceptance remains open.

### Definitive history denial — October 9, 2026

Account and transaction history hold independent view-local rows. Their catch paths previously kept
those rows even after the server explicitly denied the current resource; workspace refresh eviction
alone does not cover this history request path. These two views now clear rows and pagination after
permission/resource denial, while retaining observations for temporary connectivity failures.
Application error mapping recognizes HTTP 401/403/404 before localized-message heuristics, so the
classification cannot depend on English server wording. Other status mapping and auth refresh remain
unchanged. This is scoped protection, not proof that every independently cached history is audited.

Focused native coverage checks definitive versus temporary errors, production view eviction wiring,
and the existing revoked-payoff-access regression. The source-wiring assertion is not a UI runtime
test. No server, database, or Simulator data is modified. No migration or server restart is required.

The same view-local retention defect was confirmed in structure (categories/groups), payee, target,
schedule, delegated policy, private payoff-plan and allowance histories. Their initial/continuation
read catch paths now discard denied rows and reset pagination via the shared policy. Allowance denial
clears both its issuance and policy arrays rather than leaving one half visible after a partial read.
Transient failures still retain previously loaded observations. This does not claim proactive removal
before a denial is received, nor complete coverage of report/ledger/import/member-event caches.
