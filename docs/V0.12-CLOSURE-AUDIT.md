### Read-cache endpoint namespace correction

Read caches used host/port/user/budget filenames, omitting URL scheme and base path. APIClient
supports distinct base paths; restored authorities can legitimately preserve user/budget IDs.
Different instances on one host could therefore share a read cache even with matching access
revision. New read-cache filenames use an opaque length-framed JSON/SHA-256 namespace containing
scheme, case-normalized host, effective port, base path, credential subject and budget ID. Equivalent
default-port/root-trailing-slash spellings share a namespace; different schemes/paths/ports/users/
budgets do not. Token rotation does not change it. No credentials or readable endpoints are stored
in the filename. Access/month payload validation remains independently required.

Ambiguous old disposable read files are not automatically adopted. One successful online refresh
populates the new namespace; Local Device financial authority, attachments and pending transactions
are untouched. This is not a claim of offline availability for an unmigrated legacy cache before
that refresh. Direct production-helper/cache execution passed endpoint separation, equivalent URL
spelling, actual JWT-subject separation and token rotation alongside prior cache cases. Native tests
add those namespace cases; regular Xcode 27.0 app/native-test build-for-testing and diff checks
passed. Native execution and human runtime remain
pending; app rebuild required, no server restart/migration. TestFlight remains on hold.

**Gap confirmed at the read-only checkpoint, superseded by the outbox adoption checkpoint above:**
the transaction outbox then used the older host/port namespace.
