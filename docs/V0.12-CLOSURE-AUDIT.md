## Confirmed engineering gaps

The two originally confirmed allowance-plan gaps are now corrected in the production detail:
25-row continuation exposes earlier plan decisions, and Funding rule details explain authoritative
before/after recipient, source, amount, cadence/date, rollover, pause state and destination splits.
Requests are overlap-guarded, short/final pages stop continuation and failures retain loaded rows.
All monetary descriptions use the canonical Hide Amounts formatter and category names are qualified.

Allowance issuance history now also supports optional bounded limit/offset reads with stable ordering,
authorization before pagination and backward-compatible unpaged reads for older clients. The shared
detail uses 25-row pages with explicit earlier-issuance loading, ending on the final page and retaining
loaded rows on errors. Server and Demo preserve their existing authorization and accounting paths.
This closes the confirmed issuance scale gap; consolidated human interaction acceptance remains open.

Other mutable histories still require a scope-by-scope read/export audit; endpoint existence alone
does not prove complete explanation, pagination, migration preservation or privacy. No unsupported
claim of full v0.12 coverage is made here.

Category/group history inspection found that the original presentation explained only the first
recognized field change, despite retaining complete snapshots. Expandable Change details now expose
all changed names, groups, symbols, notes, sort order, archive state, essential/emergency classification
and delegated member. Current authorized workspace names resolve resource identities; unavailable
groups/members receive neutral labels rather than raw identifiers. Identity changes remain observable
even when both names resolve to the same unavailable label. Creation has explicit unset before-values,
and unchanged fields are omitted. This is read-only explanation, not a new accounting model.
