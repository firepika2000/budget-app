# v0.3.0 personal review checkpoint

## Implemented

- Original five-tab native information architecture over the unchanged v0.2 accounting foundation.
- Deterministic Soto Household demo with 12 months of data, accounts, targets, card reserves, debt, schedules, requests, allowances, splits, and attachments.
- Owner, partner, teen, and child persona switching with restricted presentation.
- Home attention flow, monthly Plan, category details, Smart Funding preview, money movement, goal creation, searchable Activity, transaction entry, Accounts, credit presentation, reconciliation, Insights, debt payoff, plan cost, and forecast.
- Consistent amount privacy, light/dark appearance, native Dynamic Type controls, status text/icons, semantic accessibility grouping, and chart descriptions.

## Known UX questions for hands-on review

- Is Home’s attention hierarchy calm enough, or should the forecast move below recent activity?
- Should Smart Funding be named “Fund My Plan,” “Plan Funding,” or remain “Smart Funding”?
- Does a child need separate Spend and Save tabs, or is the permission-shaped five-tab shell appropriately consistent?
- Should Plan show Assigned/Activity/Available simultaneously on wider phones, or retain progressive disclosure?
- Is the owner persona switcher too development-oriented for a future production household switcher?
- Which report deserves the default Insights landing position after real household use?

## Deferred deliberately

- All bank/institution integrations.
- Production attachment binary storage.
- First-class payee management and learned categorization.
- Server-side report aggregation and search pagination.
- Offline live-data mutation queue and conflict UI.
- Widgets, receipt OCR, and advanced animation polish.
- Persisted loan metadata and historical principal/interest attribution.

These are not silent omissions; each is marked conservatively in `feature-parity.md` and bank synchronization is gated by `bank-sync-readiness.md`.
