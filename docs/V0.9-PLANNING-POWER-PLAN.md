# Planning Power — implementation and acceptance plan

Status: **AUDIT STARTED — no claim of engineering or human completion**.
Sequencing: approved production-readiness mission, following v0.8 automated closure. Historical
v0.9 consumer server distribution is retained separately in ROADMAP.md, not replaced by this plan.

## Existing production foundation

- Categories/groups, monthly assignments, positive rollover and Move Money are canonical allocation
  operations. Do not introduce a second planning ledger.
- Target CRUD supports monthly funding, savings balance, by-date and recurring-expense metadata,
  minimum contribution, priority and active/inactive state. The shared editor exposes those inputs.
- Plan shows target recommendations/underfunding and a Monthly plan cost summary. Smart Funding
  previews before explicit commit, bounded by authoritative RTA and delegated authorization.
- Favorite/focused categories and future-month navigation already exist. Audit their correctness and
  production reachability before adding parallel controls.

## Proven source-level gaps requiring regression reproduction

1. `planning.target_funding` currently divides by the original due date for recurring expenses;
   it does not use saved `recurrence_months`. The Demo snapshot duplicates that omission. Reproduce
   after the first due month, then define the effective occurrence in the selected planning month.
   Preserve date-only arithmetic, anchor day/month-end behavior, exact ceiling division, existing
   savings and by-date semantics, and the rule that guidance never moves money.
2. No month-specific target snooze was found. Active/inactive is persistent global target metadata,
   not a substitute for snoozing one planning month. Specify storage, permissions, historical
   behavior, reporting and reactivation before adding a schema or UI.
3. Monthly plan cost currently sums target recommendations. Verify the label, target-free categories,
   minimums, scheduled obligations, visibility and future months. Do not imply all real expenses are
   covered or double-count target and schedule guidance.

## Delivery order

1. Recurring target correctness: shared exact fixtures, HTTP selected-month/Smart Funding behavior,
   Demo/Live parity and reload/money-neutral regressions. Avoid unrelated target redesign.
2. Month-specific snooze: explicit preview semantics and scoped persistent metadata with safe
   populated migration, canonical service, shared UI and restore/export inclusion.
3. Focused planning, cadence discoverability and Cost of Plan closure using existing surfaces.
4. Broad accounting, authorization and native production-composition regression checkpoint.

## Recurring target guidance correction (automated checkpoint verified)

The regression was reproduced before implementation: an annual 120000-minor-unit target anchored
January 31, 2027 recommended 120000 in February rather than 10000 toward January 2028. Both the
server and Demo previously ignored cadence. Recommendations now use the first anchored occurrence
whose month is not earlier than the selected planning month. The due month remains included in
the remaining contribution periods. Skipped cycles advance directly from the original anchor;
February clamping does not permanently change a January 31 or leap-day anchor.

The target CRUD response retains the saved anchor. The selected-month summary's `target_date`
reports the effective occurrence, so Plan does not show a stale deadline beside new guidance.
Dates beyond year 9999 are omitted instead of fabricated, while period arithmetic remains exact.
By-date targets remain overdue; they are not automatically made recurring. Existing minimum,
positive carry and current-assignment semantics remain unchanged. Guidance does not allocate money.
No schema migration is needed. A provider-neutral BudgetCore helper replaces Demo's inline formula;
shared JSON vectors are consumed by Python and Swift, including Int64 maximum ceiling division.

Backend verification: **350 passed, zero skips**, including real disposable PostgreSQL gates and
the Live HTTP month/Smart Funding/reload non-mutation case. Package verification: **39 BudgetCore +
47 BudgetAPI tests passed**. The initial native run exposed legacy Demo seed dates such as
`December 2026`; these were previously silently tolerated rather than matching the API date shape.
Seed dates are now ISO Gregorian values. The failed run is retained. Final native run: **89 XCTest

iPhone 17 Pro Max/iOS 27 Simulator. Focused target/planning/financial/debt vectors: **45 passed**.

## Incremental Smart Funding correction (automated checkpoint verified)

The HTTP regression reproduced a second preview proposing 30000 more after all 70000 of monthly
recommendations were already funded. Preview now requests only positive `underfunded_minor`, caps
each allocation by existing RTA and preserves negative RTA rather than displaying a fictional zero.
Recommendation/name ordering is preserved with a stable category-ID tie-breaker. Demo preview now
uses the same BudgetCore monthly target calculation as its summary, including cadence, minimums,
inactive targets and current assignments. It no longer uses a separate target-minus-balance rule.
Demo confirms only a current nonempty preview, checks all arithmetic before applying any allocation,
and rejects restricted/repeated/stale requests. Live's canonical allocation/version/capability path
is unchanged. No schedule or future income is treated as spendable money.

Full backend: **351 passed, zero skips**. Native: **90 XCTest + existing Plan XCUITest passed**.
Swift: **39 Core + 47 API passed**. Additional production Smart Funding sheet test **passed**:
open → cancel → reopen → confirm → refreshed empty preview with confirmation disabled.
Xcode 27 Beta/iOS 27 existing Simulator build/test succeeded; no reset or Live operation.

## Required invariants and tests

- Recommendations, snooze and previews do not change Working/Cleared/Uncleared balances, RTA,
  Assigned/Activity/Available, reconciliation, card liability or payment reserves.
- Only explicit canonical allocation commit moves existing money; no future income is spendable.
- Exact Int64-compatible minor-unit arithmetic; half-cent/ceiling behavior is specified in fixtures.
- Category/account/member scopes and revoked permission are enforced before suggestions/totals.
- Recurrence covers before/during/after due month, multiple skipped cycles, annual cadence,
  January 31/leap-year anchors, stale dates and valid date-range boundaries.
- Historical and future planning queries are deterministic and do not mutate target dates.
- Cancel/read/refresh remain money-neutral; saved metadata survives provider reload.
- Test only disposable data. Human Live remains at 0020 and is not migrated during this run.

Human acceptance: **PENDING — DO NOT RETEST**. Consolidate changed planning workflows later;
do not ask for repetition of previously accepted allocation and transaction workflows.
