This inventory traces the production report contract rather than treating rendered charts as proof of
correctness. Every Live aggregate is server-authoritative and visibility is applied before aggregation;
Demo translates the same API models into the same production views.

## Chart semantics and invariants

- Spending donut angle is exact category/group minor-unit contribution divided only for geometry;
  ranked rows retain exact integer amounts and deterministic descending order.
- Spending, cash-flow, plan, net-worth, and debt charts use dates on X and exact minor units on Y.
  Calendar-month APIs return explicit month points; line histories use server observation points.
- Net worth invariant: `assets_minor + liabilities_minor == net_worth_minor` (liabilities are signed).
- Spending excludes transfers/card payments, includes card purchases once, nets refunds and classified
  interest as ordinary spending exactly once, and nets void/reversal pairs.
- Plan invariant: category Available is canonical Assigned + Activity; targets are guidance and never
  create money. Credit-card reserve behavior remains in the accounting engine, not report UI.
- Debt classification is descriptive metadata on posted activity, never an additional ledger amount.
- Charts provide purpose/range/current totals through accessibility labels and exact rows after visual
  marks; color is not the only series distinction where multiple series exist.

## Information architecture decision

The former single long list mixed nine report concepts and export controls. The hub now contains at
most five snapshot values, four focused native navigation destinations, and one forward-looking margin.
Spending & Income, Plan Performance, Net Worth, and Debt & Interest own their charts and explanations.
Debt uses Overview / Interest / Payoff progression; future payoff and strategy UI belongs there only.

## Recorded-interest category privacy correction (2026-09-17)

A new HTTP regression exposed a gap within an otherwise visible credit account: debt reporting
filtered account IDs but aggregated classified interest from hidden categories, including a split
with one hidden category. The test reproduced 13,000 minor units where the member's visible history
contained only 1,000. The correction applies the browser's whole-transaction category visibility rule
before range/month/YTD/trailing totals, per-account interest and the first-classified date. The
separately authorized account balance remains complete, preserving canonical debt and net worth.
Unrestricted owners retain their complete recorded-interest history. No migration is required.

## Loading follow-up

The UI no longer constructs detailed chart views at the hub. The current workspace snapshot endpoint
still hydrates report payloads together, so this checkpoint improves rendering/comprehension but does
not yet reduce Live request count. Splitting snapshot hydration requires an explicit repository contract
change and must retain coherent loading/error states; it is tracked as the next performance refinement,
not falsely claimed by this visual restructuring.
