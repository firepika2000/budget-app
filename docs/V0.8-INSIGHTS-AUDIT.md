## Chart semantics and invariants

- Production-composition correction (2026-09-18): Debt Overview now actually renders the recorded
  history chart and expandable exact observations. A previously unused chart view did not prove
  production availability. Native UI coverage verifies both through workspace navigation.
- Time-series Y axes format minor units as currency; X ticks use at most six actual observation
  dates with month/year labels. Debt marks expose exact dated currency accessibility values.
- Home/Insights largest-text evidence now uses UIKit's valid accessibility size identifier;
  previous literal launch arguments were ignored and are not valid large-text proof. Four focused
  UI tests and 87 native tests pass; comprehensive human VoiceOver acceptance remains pending.

- Spending donut angle is exact category/group minor-unit contribution divided only for geometry;
  ranked rows retain exact integer amounts and deterministic descending order.
- Spending, cash-flow, plan, net-worth, and debt charts use dates on X and exact minor units on Y.
  Calendar-month APIs return explicit month points; line histories use server observation points.
- Net worth invariant: `assets_minor + liabilities_minor == net_worth_minor` (liabilities are signed).
- Spending excludes transfers/card payments, includes card purchases once, nets refunds and classified
  interest as ordinary spending exactly once, and nets void/reversal pairs.
- Plan invariant: category Available is canonical Assigned + Activity; targets are guidance and never
  create money. Credit-card reserve behavior remains in the accounting engine, not report UI.
- Debt classification is descriptive metadata on posted activity, never an additional ledger amount.
- Charts provide purpose/range/current totals through accessibility labels and exact rows after visual
  marks; color is not the only series distinction where multiple series exist.

## Information architecture decision

The former single long list mixed nine report concepts and export controls. The hub now contains at
most five snapshot values, four focused native navigation destinations, and one forward-looking margin.
Spending & Income, Plan Performance, Net Worth, and Debt & Interest own their charts and explanations.
Debt owns progressive recorded, estimated and projected views; payoff and strategy UI belongs there only.

Current progression is Overview / Interest / Cost / Payoff. Cost is an explicitly approximate
unchanged-balance monthly observation, not a projected full repayment schedule or a recorded charge.
It does not guess daily-average-balance, grace-period or fee rules. Unknown APR stays unknown, while
an explicit zero APR produces an exact zero estimate. Missing payment/due terms do not prevent this
limited estimate; they still prevent a payoff projection. Weekly/biweekly actual charge timing is not
asserted. The server batches canonical balances and joins terms after account visibility is applied;
restricted users cannot probe hidden or cross-budget rates through selectors or resource errors.
Live resolves the current credential for each request. Demo uses its fixture observation date and
the same integer engine. Neither provider writes financial state by viewing Cost.

## Recorded-interest category privacy correction (2026-09-17)

A new HTTP regression exposed a gap within an otherwise visible credit account: debt reporting
filtered account IDs but aggregated classified interest from hidden categories, including a split
with one hidden category. The test reproduced 13,000 minor units where the member's visible history
contained only 1,000. The correction applies the browser's whole-transaction category visibility rule
before range/month/YTD/trailing totals, per-account interest and the first-classified date. The
separately authorized account balance remains complete, preserving canonical debt and net worth.
Unrestricted owners retain their complete recorded-interest history. No migration is required.

## Loading correction completed (2026-09-18)

Ordinary Live core hydration now requests zero report payloads. The hub loads one bounded summary;
each focused destination loads only its required reports. Identical concurrent reads share work and
date/filter, core-state and credential revisions invalidate cached results. Report failures have
independent Retry and Reset range and filters actions, without blocking Home. Production tests cover
request counts, rotated credentials, context changes and navigation. The 10,000-transaction synthetic
fixture measures summary response size and SQL fan-out; detailed server calculations still run behind
the summary, so this is not a claim of constant CPU cost. See the production-readiness ledger.
